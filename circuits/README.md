# ZK Wordle-Duel — feasibility spike

A self-contained Noir + Barretenberg spike that validates the hard unknowns of a
**fully trustless, chain-only mutual-duel** Wordle PvP before committing to the
full design. See the plan in `~/.claude/plans/` and `async_pvp_wordle_plan.md`
for the broader game context.

**What this proves (one direction, one guess):** that a 5-tile Wordle `feedback`
is the correct scoring of a public `guess` against a _private_ `secret` word,
and (step 4) that the secret opens a public Poseidon `commitment`. Dictionary
membership, turn alternation, escrow, and the second player's direction are
deferred.

## Encoding conventions (keep in lock-step everywhere)

- Letters `a..z` → `0..25`.
- Tiles: `absent=0, present=1, correct=2`.
- Feedback packed base-4, least-significant tile first: `Σ tile_i · 4^i`.
- Scoring is a bit-exact port of `src/lib/game.server.ts::evaluateGuess`
  (two-pass, left-to-right first-unused-match). Pinned by tests lifted from
  `src/lib/game.test.ts`.

## Commands

bb 5.x replaced `--scheme/--oracle_hash` with `-t <verifier_target>`. We use
`-t evm` = Ethereum/Solidity (keccak transcript, ZK).

```bash
cd circuits
nargo test            # scoring + commitment vectors (8 tests)
nargo execute         # solve witness from Prover.toml -> target/wordle_feedback.gz
nargo compile         # -> target/wordle_feedback.json (ACIR)

bb gates -b target/wordle_feedback.json
bb prove -b target/wordle_feedback.json -w target/wordle_feedback.gz -o target/ -t evm --write_vk
bb verify -k target/vk -p target/proof -i target/public_inputs -t evm
bb write_solidity_verifier -k target/vk -o ../contracts/zk/WordleVerifier.sol

# Solidity end-to-end (from repo root):
forge test --match-path "test/zk/WordleVerifier.t.sol" --gas-report
forge build --sizes        # HonkVerifier runtime size vs EIP-170 (24576)

# Proving harness (browser/mobile proxy):
bun install                # in circuits/
bun run scripts/prove.ts             # single-thread WASM (mobile proxy)
BB_THREADS=0 bun run scripts/prove.ts  # multi-thread comparison
```

Note on public inputs: `target/public_inputs` holds the **7** circuit public
inputs `[commitment, guess[0..5], feedback]`. The generated verifier reports
`NUMBER_OF_PUBLIC_INPUTS = 15` because it adds 8 pairing-point limbs — but those
live **inside the proof**, so `verify(proof, publicInputs)` takes the 7-word array.

## Metrics (measured — circuit = scoring + Poseidon2 commitment, no Merkle)

| Metric                        | Value                         | "Good" ballpark             | Verdict      |
| ----------------------------- | ----------------------------- | --------------------------- | ------------ |
| Gate count (`circuit_size`)   | **631** (435 ACIR opcodes)    | low-thousands–low-tens-of-k | ✅ far under |
| Proof size                    | **6,464 B** (202 fields)      | ~few KB                     | ✅           |
| Proving time (native, 10 thr) | **~1.0 s** wall (0.26 s user) | sub-s–few s                 | ✅           |
| Proving time (WASM, 1-thread) | **787 ms** (98 ms multi)      | ≲ ~10 s (mobile proxy)      | ✅           |
| Verify gas (Gnosis EVM)       | **~2.08 M** median            | —                           | ⚠️ see note  |
| Verifier deploy gas           | ~3.91 M (one-time)            | —                           | ✅           |
| Verifier runtime bytecode     | **17,827 B** (6,749 B margin) | **< 24576 (EIP-170)**       | ✅ PASS      |

> **Verify gas note:** ~2.08 M is the **ZK** UltraHonk verifier (the ZK variant
> is required to keep the secret word private). That's higher than a non-ZK
> UltraHonk (~600 k), but at Gnosis gas prices (~1–2 gwei, xDAI) it costs a
> fraction of a cent per verification, so gas is **not** the binding constraint.
> (Optional keccak-commitment delta was not measured — Poseidon already lands far
> under every threshold, so keccak parity is unnecessary for the spike.)

## Go / no-go — verdict: **GO** ✅

All gates pass for a chain-only mutual-duel ZK PvP on Gnosis with Noir + bb:

- **Verifier bytecode 17,827 B < 24,576** (EIP-170) — the hard gate clears with
  6.7 KB to spare, even with the optimizer at 200 runs.
- **Verify gas ~2.08 M** — sub-cent on Gnosis; acceptable (it is NOT ~600 k, but
  that figure was for non-ZK; ZK privacy is worth it and Gnosis is cheap).
- **Mobile-proxy proving 787 ms** single-thread desktop WASM — comfortably under
  10 s. Even a 5–10× real-device penalty (~4–8 s) stays acceptable for a
  per-guess proof.
- **Gate count 631** — enormous headroom to add the deferred depth-12 Poseidon
  Merkle dictionary-membership (~12 permutations) without nearing any threshold.

**Remaining real-world validation before full build:** (1) prove on actual
iOS Safari / Android WebView (the true worst case vs Node WASM); (2) add and
re-measure dictionary membership; (3) design the full duel state machine,
on-chain match/escrow contracts, and per-guess proof submission flow. If a future
target chain has expensive gas, or per-duel proof volume balloons, revisit
recursive aggregation. None of these threaten the core feasibility.
